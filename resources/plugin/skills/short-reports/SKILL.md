# Short reports

- The first line is a one-line `RESULT:` summary: what changed and where it stands.
- Below it, only what the user needs: what is left, what you could not verify, what you decided for them.
- Don't narrate the process (what you read, in which order).
- Don't paste whole code. Point to file:line when needed.
- PR body: 3 to 5 lines of changes, test results, and where reviewers should look.
